# 产品目标

> 本文回答**做什么、先做哪个、什么不做**。`plan/master-plan.md` 只回答按什么顺序做、每步验收什么；顺序服务于这里的优先级。功能范围变了先改本文，再让 master-plan 引用过来——反过来（plan 里长出功能）就是漂移。

## 定位

一台机器上的个人超级智能体：编码与日常事务共用一个持久化内核（`packages/kernel/durable`），数据全在本地。分界线在“日常”那一半——纯编码 agent 已有现成产品，能长期记忆、主动唤醒、找到你的才是本文要做的东西。

## 一年成功判据

不数功能清单，数使用行为：**一年后如果你没在用它、而是在用别的工具，这个版本就算失败。**

之后每月末尾复验一次下面三件事；连续两个月有任何一件没做成，说明优先级排错，回「首批功能」表调排序，而不是加功能。

1. **编码**：一个带真实文件改动的任务（改代码 → 跑测试 → 修到绿）由它自主完成，会话与任务状态断点可恢复。
2. **日常**：一天的待办与提醒由它记录、调度、到点主动推送找到人，不靠打开界面查。
3. **记忆**：隔一周提起上周的决定或文件，它能从持久化数据里答出来，不是靠重新粘贴上下文。

## 首批功能

排序判据只有一条：**它越早存在，“每天在用”越早成立。** 承载形态（feature 包 / provider / seat）由 `docs/structure.md` 与 `docs/kernel/seats.md` 决定，这里不写。

| 优先级 | 能力 | 它替用户做成什么 | 落到 plan 的位置 |
| --- | --- | --- | --- |
| 1 | 对话 + 编码工具竖切 | 指哪改哪、跑通验证 | master-plan P2 |
| 2 | 长期记忆与检索 | 跨会话记住决定、文件、偏好 | P2 之后第一个功能 |
| 3 | 定时与主动任务 | 到点干活，不用人守 | 紧随其后 |
| 4 | 通知推送 | 任务跑完找到人：桌面通知，之后手机 | 与 3 同期评估 |
| 5 | 检索（网页 + 本地全文） | 回答不靠上下文快照现编 | 网页检索随 3 需要时做；本地全文在记忆数据够厚时做 |

MCP 内核包已在，连接器（日历/邮件/IM）经 mcp provider 接入，不新开顶层形态；没有消费者就不建空包。

## 明确不做

| 不做 | 为什么 |
| --- | --- |
| 多用户与账号体系 | 一台机器一个主人；远程接入是同一个主人的延伸，不是第二个用户 |
| 云同步、Web 托管 | 与“数据全在本地”的定位冲突 |
| 运行期第三方插件 | 编译期内置 features 已覆盖（理由见 `docs/structure.md` §16）；宿主侧 spike 在 P5 |
| 模型训练与微调 | 用现成模型，经 `ai` 包接入 |
| 移动 app | 手机只做远程控制端 |

想进清单的东西必须先在本文件立住“替用户做成什么”一句，才允许进 master-plan 的阶段表。
