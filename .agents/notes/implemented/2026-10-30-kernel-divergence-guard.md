# 内核改动必须有账本，账本必须有机器核对

- 背景：`KERNEL.md` §2 允许按三档改内核，`docs/kernel/divergence.md` 是唯一账本，但它从建立起到今天条目为空，而机检那一行写着"脚本待建，当前靠纪律"。同时 `packages/kernel/` 是 pi 1.4.0 的快照移植，与上游没有共同 git 历史：一旦某个文件被改了而没人记，将来回补时它要么被当成"未偏离"整体替换（丢改动），要么退化成全文件三路合并（丢 O(1) 优势）。纪律在这个仓库已经被证明会失效——`KERNEL.md` 与 `divergence.md` 各自留了一句"待建"。
- 决定：新增 `scripts/check-kernel-divergence.mjs`，把 `scripts/kernel-baseline.json` 作为基线物证。基线记录的是**建立基线那一刻**这棵树的内容 hash，外加两组路径集合（上游有本地无、本地有上游无）。与上游的差异由 `docs/migration/deviations.md` 的 D0–D18 解释，不重复记账。此后任何差异（新增/修改/删除/恢复）必须在 `divergence.md` 或 `deviations.md` 里以路径（或 glob）被命名，否则红。`--write` 是唯一写入口：它先按旧基线算一次差异，**拒绝吸收任何没被账本命名的改动**；「同一次提交」由 pre-commit 比对暂存区配对。
- 被拒绝的替代方案：
  - **直接 diff `.upstream/*-normalized`**：`.upstream/` 在 `.gitignore` 里，CI 与全新 clone 都没有它。一个只在"跑过 `sync-upstream` 的机器"上生效的守卫，正是 `check-gate-registration` 要拦的那种"看起来存在、从不运行"。
  - **基线 = 上游归一化 hash + 逐项豁免清单**：实测不可行。把基线取成上游后，第一次运行报出 253 个"未记录差异"，其主体来自 D1（scope 改名）、D10（格式化重排 import）、D11（`pi.*` → `naveti.*` 标识符 rebrand）——这三条是全树性的，路径级记账在迁移期没有分辨力，只会变成"全部豁免"或"全部红"。路径级检测在迁移**结束的那一刻**才有全部价值，所以把基线定在那一刻，之前的差异交给 D 条目 review。
  - **继续靠纪律**：就是上一行那句话本身。它已经失效过。
- 后果：
  - **明确边界**：基线建立之前的"意外改动"无法被此守卫发现（它们已被 D0–D18 覆盖过一次人工 review，这是本决定的信任前提）。基线之后的每一处改动都会被拦。
  - `--write` 不依赖 git：它审计的是"即将被吸收的差异是否已被命名"。"同一次提交"由 `check` 模式读 `git diff --cached` 完成，因为工作区干净与否看不见"暂存后又还原"。
  - 守卫证明的是"改动被**提到**"，不是"理由说得对"。账本 diff 才是审查物，与 `test-integrity.json` 同构。
  - `--write` 每次都会打印"本树与 pi 1.4.0 的差异规模"，并逐条列出它吸收的路径，所以重新基线永远不会是静默的。
  - 重新考虑的条件：若决定不再跟随上游（停止回补），此守卫的退役条件已写在 `structure.md` §13 的表里。
  - **实施修正（2026-10-30，同日）**：最初版本有三处已在当日修掉的问题——(a) `PATH_TOKEN` 把 `js` 排在 `json` 前，`*.json` 被截成 `*.js`，导致账本对自己最重要的豁免条目（D2 的生成物）视而不见；(b) `--write` 只要求"账本文件脏了"，能被"改一处内核 + 账本加一句无关的话 + 重基线"洗白；(c) 上游独有的路径完全不可见，"恢复了上游文件"会被当成普通新增。另外文件从 `upstream-baseline.json` 改名为 `kernel-baseline.json`——旧名会让人以为它是上游快照，而它存的是本树 hash。
