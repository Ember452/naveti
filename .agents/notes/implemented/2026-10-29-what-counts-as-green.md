# 什么算绿：以密封环境下的单进程运行为准

- 背景：迁移文档写的"全绿"与本机能复现的"绿"不是同一件事——`chord` 有 8 个用例红着，因为工作树里 `tutorial.md` 是 CRLF 而测试按 `\n` 匹配代码块。数字写进文档时没人对照过工作区。同一时期 `durable` 有 5 个 symlink 用例在 Windows 上必红，却被当作"预期失败"长期挂着，红到没人读。
- 决定：绿色只有一个口径——`pnpm check` + `pnpm build`（离线）+ `pnpm test:ci`（单进程 + 密封环境：临时 HOME、无 API key、不设用户 git/npm 配置、`TZ/LANG` 固定）。平台限制必须分类记录：能条件跳过的改成带可见名字的 skip，不能跳过的写进 `migration/baseline.md` 并说明"红不算回归"。数字只写一处，两份数字必然分叉。
- 被拒绝的替代方案：保留"本机永远不全绿"的状态。它把红变成噪音，而噪音的代价是下一次真的红也没人看。另一个替代是"只跑 CI 不看本机"——本地反馈从 4.5 分钟变成 10 分钟加一个 push。
- 后果：`baseline.md` 成了仓库里唯一逐项可复核的文档（6040 + 879 = 各包之和），Ubuntu 与 Windows 两侧数字并列且差异有解释。代价是每次改变测试清单都要更新它，因此有了测试清单棘轮（见同日另一条）。
