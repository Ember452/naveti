# 测试清单棘轮：不允许静默减量

- 背景：门禁可以被三种不报错的方式变绿——删测试、加 `.skip`、把用例藏进永远为假的条件里。这些都不是"代码错了"，所以没有任何守卫会红；而 AI 协作时它们是最常被走的路。
- 决定：`scripts/test-integrity.json` 冻结每个测试文件的声明数与各类 skip 数，只允许"测试变多、skip 变少"的方向；`.only` 与 `describe.skip` 直接红（前者让整轮只剩标记的用例且 exit 0）；运行时再用 `allowOnly: false` 兜一层。要合法改动就 `pnpm run test-integrity:write`，让 JSON diff 出现在同一个提交里。
- 被拒绝的替代方案：每文件设 skip 上限 + 每项写 reason。上限是拍出来的数字，合法新增时要抬，抬这一步没有审查价值；reason 是自由文本，没人读。清单棘轮的好处是 diff 自带"哪个文件丢了多少覆盖"。
- 后果：这是**文本计数**，能抓"少了一个用例"，抓不到"断言被注水"（`toBe(4)` → `toBeGreaterThan(0)`）。后者只能靠黄金文件与人工验收，`tests/golden/` 目前未建——这是已知缺口，不是已完成项。
