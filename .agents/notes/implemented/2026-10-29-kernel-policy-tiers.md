# 内核改成"三档变更 + 门面 + 分歧账本"，不再冻结

- 背景：迁移后的策略是"内核冻结，只摘取上游安全补丁"。它只对"短期不动"成立。一旦确定将来要按产品需要改内核，冻结就把改动变成没有落点的例外——最后以"偷偷打补丁"的形式发生在内核深处，既没测试也没记录。
- 决定：`KERNEL.md` 定义三档（A 加扩展点 / B 改语义 / C 结构手术）与各自的验收；`packages/platform/host/src/extend/` 是产品层唯一可见的内核面（显式清单，禁 `export *`）；`docs/kernel/divergence.md` 记录每一处偏离（文件、为什么、风险、用什么测试兜住、上游状态）；回补策略从"摘补丁"改为"没改过的文件可整体替换，改过的走账本"。
- 被拒绝的替代方案：保持冻结 + 只在万不得已时打补丁。代价是改动无法审计；另一个替代是彻底 fork 放弃上游，代价是安全修复要自己重新发现。
- 后果：改内核的传导面固定为门面，功能包不因内核重构而改动。代价是每次内核 API 变化都要在门面补一层，且 B 档必须同时写迁移脚本与黄金文件——`tests/golden/` 因此成为第一次 B 档改动的前置条件。
